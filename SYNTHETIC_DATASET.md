# Synthetic transaction dataset: `paysim_synthetic.csv`

Generated by our team for CS 483 (Big Data Mining, Fall 2026) with the instructor's approval. This file is **not real data and not from Kaggle**. It's a simulated month of mobile-money transactions in the same format as the PaySim dataset (Lopez-Rojas et al., 2016).

| | |
|---|---|
| Rows | 3,181,310 (same as each half of the real dataset) |
| Columns | the 11 PaySim columns, same names, order and number format |
| Period | steps 1–743 (one step = one hour, about 31 days) |
| Fraud | 4,106 rows (0.129%), the same rate as the real data |
| Generator | `generate_synthetic.py --seed 2026` (defaults); the same seed reproduces the file byte for byte |
| SHA-256 | `5b85b9047107dbfcbb329ef1a3512f761310ebfe9eeb544b1a757dc5cb98d4eb` |

## How it was made

The generator simulates customers, cash agents and merchants hour by hour. Its statistical shape is **calibrated from the real Kaggle file**, but no real row is copied.

- **Transaction mix per hour of day:** matches the real share of CASH_IN, CASH_OUT, DEBIT, PAYMENT and TRANSFER.
- **Amounts per type:** drawn from the real distributions (log-scale histograms), so medians and spreads match.
- **Daily rhythm:** busy daytime, quiet nights (82% vs 80% of activity outside hours 0–6), plus a small weekend dip.
- **Fraud follows PaySim's pattern:** an account takeover sends a TRANSFER to a fresh "mule" account, which immediately CASH_OUTs the same amount. Fraud happens evenly around the clock, never in other types, and is capped at 10M per transaction, with larger thefts split.
- **Rule-based flag:** a few fraudulent transfers over 200,000 are blocked by the bank (`isFlaggedFraud = 1`, balance unchanged).
- **No ID overlap:** customer and merchant IDs look like PaySim's (`C…` / `M…`) but never collide with any ID in the real file.

## Where it deliberately differs from PaySim

These changes make the data more realistic. They also mean a model trained on one source may behave differently on the other, which is worth discussing.

| | Real PaySim | Synthetic |
|---|---|---|
| Transactions per customer | almost always 1 | about 3.3 per month |
| Balances add up (`old ± amount = new`) | 43% of rows | 100% |
| Spending more than the balance | 57% of rows | never |
| Fraud empties the whole account | 98% | 91% (some frauds take only part) |
| Calendar | volume collapses after day 17 | steady 31 days |
| Cash agents' balances | inconsistent | tracked |
