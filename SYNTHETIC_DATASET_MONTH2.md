# Synthetic transaction dataset, month 2: `paysim_synthetic_month2.json`

The fourth and final dataset of the CS 483 fraud project, generated by our team with the instructor's approval. It's **not real data**. It continues the simulation one month past PaySim's 30 days, so the project's data covers two months in total.

| | |
|---|---|
| Rows | 3,181,310 (same as each of the other three datasets) |
| Format | one JSON array, one record per line, same layout as `paysim_second_half.json` |
| Fields | the 11 PaySim columns, same names and order; numbers stored as numbers |
| Period | steps 744–1,486: the 743 hours (about 31 days) right after PaySim's last step |
| Fraud | 4,106 records (0.129%), the same rate as the real data |
| Customers | all new: no ID is shared with the real Kaggle file or with `paysim_synthetic.csv` |
| Generator | `generate_synthetic.py --start-step 744 --steps 743 --seed 2027 --format json-array --exclude-ids-from paysim_synthetic.csv` |
| SHA-256 | `a2bcdb6fb50cb30e4d93f6ee08b820f6d0609215ff1d7d7b0fb2ba7338a0cdf5` (the command above reproduces it byte for byte) |

It uses the same generator, calibrated from the real file, as `paysim_synthetic.csv`. Its realism and its deliberate differences from PaySim are therefore the same: balances always add up, customers transact several times a month, and some frauds take only part of the balance. See `SYNTHETIC_DATASET.md` for how it was built.

**Reading it in Spark:** `spark.read.option("multiLine", True).json("paysim_synthetic_month2.json")`
